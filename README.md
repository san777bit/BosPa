# BosPa

Telegram-бот и Mini App с картой: загруженность троллейбуса №7 и автобуса №38А в Алматы по отметкам пассажиров и живые позиции бортов.

Проектные документы: `../bospa-tech-design.md`, `../bospa-live-map.md`.

## Запуск локально

```bash
uv sync
cp .env.example .env        # BOT_TOKEN — только если нужен бот
# нужен Redis на localhost:6379
uv run python -m bospa
```

Один процесс запускает API на `:8080` (Mini App и мобильное приложение), цикл слияния источников и, если задан `BOT_TOKEN`, бота (long polling). Без токена бот выключен.

### API мобильного приложения

Приложение при первом запуске вызывает `POST /api/devices` и получает `{user_id, token}`; дальше токен идёт в заголовке `Authorization: Bearer <token>`. В базе хранится только sha256 токена. У пользователей приложения отрицательные id (`-devices.id`), поэтому они не пересекаются с Telegram id, а отметки, поездки, баллы и антифрод работают так же, как в боте.

| Запрос | Что делает |
|---|---|
| `GET /api/routes`, `/api/vehicles`, `/api/stops/status` | карта; принимают токен устройства или Telegram `initData` |
| `GET /api/me` | `{user_id, balance}` |
| `POST /api/location` `{lat, lon}` | разовая геопозиция перед отметкой; без неё отметка засчитывается без баллов |
| `POST /api/checkins` `{route, dir, stop_id, level}` | отметка загруженности (`level` 0–2); `accepted: false` — сработал кулдаун |
| `POST /api/ride` `{route, dir}` | «Я в автобусе»: выбор маршрута |
| `POST /api/ride/location` `{lat, lon}` | точка поездки; первая после выбора начинает трек; 409 — поездка не начата |
| `DELETE /api/ride` | конец поездки |

`API_DEV_NO_AUTH` открывает только чтение, запись всегда требует пользователя. Ограничения частоты регистрации устройств пока нет.


## Данные маршрутов

Все маршруты в `data/routes.yaml` помечены `verified: false`: пока так, бот и карта предупреждают, что данные проверяются. После проверки на месте поставить `true`.

**38А** — кольцевой маршрут «Арман → Рыскулова → Арман», 65 остановок, 48 км. Собирается командой `uv run python scripts/build_route.py data/specs/b38a.yaml`:

- порядок остановок — публичная страница маршрута в 2ГИС; координаты — OpenStreetMap; линия по дорогам — OSRM;
- линия совпадает с ручной разметкой маршрута в OSM: все её точки в пределах 30 м;
- 8 остановок есть в 2ГИС, но нет в OSM (`approx: true`): Кульджинский тракт, Река Малая Алматинка, Омская, Айтыкова, Роща им. Баума, Москвина, Аскарова, Школа Мирас. Они стоят посередине между соседями, в карточке помечены «место уточняется»;
- на 8 участках OSRM для легковых машин делает крюк, и там стоит прямой отрезок (список печатает скрипт). Это северо-западная часть кольца: Рыскулова — Сейфуллина, Яблочкова — Лобачевского, Казыбаева — Бокейханова, Немировича-Данченко — Рыскулова — ТЦ Бакорда — Ашимова — Ахрименко, Жетысу-2 — Проспект Абая.

**№7** — троллейбус «Ж/д вокзал Алматы-1 ⇄ Ауэзова», по 34 остановки в каждую сторону, 18,5 и 19,2 км. Собирается командой `uv run python scripts/build_route.py data/specs/t7.yaml`:

- источники те же, что у 38А; каждое направление строится отдельно, поэтому остановки стоят на своей стороне дороги, а улицы с односторонним движением учтены;
- все остановки нашлись в OSM. Пять — под другими названиями (см. `osm:` в спецификации). «Тимирязева» из 2ГИС привязана к OSM-остановке «Байтурсынова» на углу этих улиц: это предположение, его стоит проверить;
- линия совпадает с ручной разметкой троллейбуса в OSM в пределах 30 м везде, кроме разворотного кольца у вокзала Алматы-1;
- прямые отрезки вместо крюков: Ломоносова — Иркутская, Маметовой — Макатаева — Гоголя (к Ауэзова); Толе би — Гоголя, Райымбека — Райымбека, Акпаева — Рыскулова (к вокзалу);
- «Райымбека» в 2ГИС указана дважды подряд — оставлено как есть, две остановки в 70 м друг от друга.

## Устройство

```
bospa/
├── domain/        чистая логика, без Redis и Telegram
│   ├── geo.py         проекция точки на линию маршрута
│   ├── routes.py      загрузка routes.yaml, остановки и отрезки
│   ├── status.py      загруженность с затуханием (полупериод 5 мин, окно 15 мин)
│   ├── antifraud.py   проверки для начисления баллов
│   ├── mapmatch.py    привязка GPS к линии, отсев пешеходов и шума
│   ├── fusion.py      слияние официального GPS и пассажиров в борта
│   └── eta.py         ETA по скоростям на отрезках
├── infra/         Redis (все ключи — redis_repo.py), SQLAlchemy-модели
├── services/      чекины, поездки, статус остановок, фоновый цикл слияния
├── sources/       источник Б: интерфейс VehicleSource и заглушка NullSource
├── bot/           aiogram: тексты, клавиатуры, обработчики
├── api/           FastAPI для Mini App и мобильного приложения, проверка Telegram initData
└── webapp/        Mini App: MapLibre, без сборки
```

## Что ещё не сделано

- **Источник Б.** Пока работает `NullSource`, борта на карте только «народные». Адаптер пишется после договорённости с акиматом, Onay или 2ГИС.
- **Награды и промокоды** (таблицы `partners`, `rewards`, `promo_codes`, обмен баллов): по плану после подключения партнёров.
- **Alembic.** Схема БД создаётся при старте через `create_all`.
- **Админ-команды** (бан, ручное начисление, загрузка промокодов).
